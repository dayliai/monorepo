How it thinks

Three steps, every time you summon it.

1

Reads

Diffs your branch against main, opens every changed UI file, and reads it in full. No partial-snippet audits.

2

Evaluates

Checks every interactive element, image, form, and modal against WCAG 2.2 AA + the Dayli design system: token rules, focus contrast, error color #B91C1C, modal pattern.

3

Reports

Returns severity-ranked findings (Blocker / Critical / Major / Minor) with file:line, the WCAG criterion, and ready-to-paste fixes — including suggested alt-text copy in the Daily Living Labs voice.

Read-only by design. The reviewer never edits your code — you decide what ships.

Three ways to summon it

Pick whichever fits your moment.

All three trigger the same review. Use the slash command for speed; spawn directly for surgical scope.

1

The default

Type before pushing any UI PR.

$ /a11y-review

Reads your branch diff, runs the full audit, summarizes the report, and asks before applying any fixes. Lives at .claude/commands/a11y-review.md.

2

Surgical scope

When you want to review one specific surface.

Tighter focus, faster turnaround. Useful when you're working through Chelsea's followup doc one route at a time.

A real audit, step by step

From "alt empty" to "ships with story-rich alt text" in five steps.

Drawn from the actual May 5 audit of the How It Works section — the umbrella illustrations on dailylivinglabs.com.

Step 1 of 5 · Before

The code as it exists

Three illustrations marked decorative. Screen reader users get nothing.

// apps/landing/src/components/HowItWorks.tsx
{
  title: 'Identify',
  image: '/images/how it works image identify.png',
  alt: '', // decorative — text below covers it (does it?)
}

Step 2 of 5 · Summon

Run the review

One slash command. The agent diffs the branch, sees the change touched HowItWorks, and reads it in full.

$ /a11y-review

▸ Spawning a11y-reviewer subagent...
▸ Diffing branch: amber/landing-tweaks
▸ Reading 1 changed file: HowItWorks.tsx
▸ Evaluating against WCAG 2.2 AA + Dayli rules...

Step 3 of 5 · Finding

A real flag, not a vague warning

🟠 Critical HowItWorks.tsx:1-23 · WCAG 1.1.1

"How It Works" images marked decorative but carry the community-narrative arc

These three illustrations tell a visual story (caregiver under umbrella → drone-built solution → solution helping a wider community). The headings — "Identify / Invent / Integrate" — convey the conceptual model but not the emotional and social context a sighted user gets at a glance. Marking them alt="" means BLV users miss the entire narrative arc.

▸ Why this is Critical, not Blocker or Minor
A keyboard user can still complete the page (so not Blocker), but a BLV user gets a measurably worse experience than a sighted user (so not Minor). The fix is non-cosmetic and meaningful — that's Critical territory.

Step 4 of 5 · Fix

Ready-to-paste replacement copy

The agent doesn't say "describe the image more." It writes the alt text for you, in the Daily Living Labs voice.

alt: '',
alt: 'A wheelchair user gestures upward while a caregiver stands beside them holding a purple umbrella in the rain — together they name a daily challenge that needs a solution.',

Notice: it specifies who is in the image, what they're doing, the scene, and connects back to the conceptual meaning. That's the rubric.

Step 5 of 5 · Confirm

Re-run, and you're conformant

After applying the fix, run /a11y-review again to confirm.

$ /a11y-review

✓ HowItWorks.tsx — conformant
▸ All informative images carry story-rich alt text
▸ 0 blockers, 0 critical, 0 major, 0 minor

// Now update docs/wcag-2.2-aa-followups-dayli.md
// and the accessibility statement to reflect the fix.

The decision the agent makes for every image

Decorative or informative?

If the surrounding text fully covers what the image conveys, it's decorative. If the image carries meaning the text doesn't, it's informative — and the alt becomes a craft job.

Decorative surrounding text covers it
Done

A checkmark icon next to the word "Done." The text already says it. The icon adds nothing for a screen reader.

alt=""
aria-hidden="true"
Informative carries meaning text doesn't

"A wheelchair user gestures upward while a caregiver stands beside them holding a purple umbrella in the rain — together they name a daily challenge that needs a solution."

A narrative illustration. The heading says "Identify" but doesn't carry the emotional or social context. Story-rich alt restores it.

alt="A wheelchair user gestures..."

The four checks the agent runs on every informative image

  • 1.Specificity. Describes what's actually visible, not "image of X."
  • 2.No genre prefix. "Image of," "picture of," "photo of" stripped — screen readers already announce the role.
  • 3.Story coverage. A BLV user gets the same emotional and social content a sighted user gets at a glance.
  • 4.Right length. Enough to convey meaning, not so much it becomes tedious. Usually 15–200 characters for narrative images.

Severity quick-reference

How to triage findings.

🔴

Blocker

A primary task is impossible for a keyboard or screen-reader user. Fix before merge.

🟠

Critical

Measurable WCAG fail that materially degrades AT experience. Fix in this PR or the next.

🟡

Major

WCAG fail or strong best-practice issue, non-blocking. Add to the followups doc.

🟢

Minor

Polish, defensible either way. Optional.
